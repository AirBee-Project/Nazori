# Nazori テスト方針と使い方

本プロジェクトのテストは、主に**スナップショットテスト**を用いて以下の2点の方針で行います。

## 1. 出力ができることの検証
PLATEAUのデータは様々な形式（年度によるデータ形式の差分など）があり得るため、パースが完了して様々な年度・種類のPLATEAUデータが読み込めることを検証します。
パース中にエラー（例: ポリゴンが閉じていない等）が発生した場合でもテストを落とすのではなく、エラー自体をスナップショットに記録し、特定のデータにおいて期待通りにエラーが検知されることを担保します。

## 2. 出力結果の一致の検証
出力結果（空間IDのリスト）が過去の正解データ（スナップショット）と一致するか検証します。
Kasane-Logicの改良等により空間IDの出力結果がずれる場合がありますが、その差分はテストツールによって自動で可視化されます。人間がその差分（diff）を確認し、許容範囲内（妥当な変更）であると判断した場合は新しいスナップショットとして承認します。

---

## テストの実行方法 (instaの利用)

本プロジェクトではスナップショットテストのフレームワークとして [insta](https://insta.rs/) を利用しています。`sample/plateau/bldg` や `sample/plateau/tran` フォルダ以下にある `.gml` ファイルはテスト実行時に自動的にスキャンされます。

### テストの実行

通常のテスト実行と同じコマンドで行います。

```bash
cargo test
# または特定のテストのみ実行する場合
cargo test --test plateau
```

過去のスナップショットと結果が一致すればテストは成功（PASS）します。新しいサンプルを追加した直後や、ロジックの変更で結果が変わった場合はテストが失敗（FAIL）し、`.snap.new` という新しい結果ファイルが生成されます。

### 差分の確認と承認

テストが失敗した場合（または新規スナップショットが生成された場合）は、以下のコマンドで差分をレビューします。（事前に `cargo-insta` をインストールしておくことを推奨します）

```bash
# cargo-insta のインストール (初回のみ)
cargo install cargo-insta

# スナップショットの差分を対話形式で確認・承認する
cargo insta review
```

`cargo insta review` を実行すると、コンソール上に変更前の結果と変更後の結果の差分（diff）が表示されます。
- 差分が妥当であれば `a` (accept) を入力してスナップショットを更新します。
- 意図しないエンバグであれば `r` (reject) してコードを修正してください。

一括で全て承認しても良い場合は、以下のコマンドを使用することもできます。

```bash
cargo insta accept
```

### サンプルデータの追加方法

新たにテストケースを追加したい場合は、`sample/plateau/bldg/` や `sample/plateau/tran/` 内の任意の場所（サブフォルダ含む）に新しい `.gml` ファイルを配置するだけです。
次回 `cargo test` 実行時に自動的に新しいファイルが検出され、新しいスナップショットの作成が促されます。

- エラーが確認されたサンプルデータは追加して、以後の同じエラーの発生に備えること
- PLATEAUの様々な年度とバージョンのエラーを網羅することで広範にエラーを検知すること
